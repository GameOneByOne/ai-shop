# 1688 SourceSKU 解析规则

本文档记录浏览器扩展从 1688 商品详情页生成 `SourceSKU` 的 Phase 1 规则。实现位于 `browser-extension/page-scraper.js`，修改解析器时必须同步更新本文档和回归测试。

## 目标

从详情页可售子产品中读取名称、图片、当前页面价格和库存。这里的 `SourceSKU` 表示真实可采购子产品，不负责 ProductModel 归并、AI 评分或采购推荐。

## 解析边界

只处理两个商品属性区域：

- 一级选项：`颜色`、`款式`或`型号`。
- 二级选项：`规格`或`尺寸`。

以下附加服务不生成 SourceSKU，也不能参与 SKU 数量：包装、加字、加圈、贴牌、换标、定制、商标、标签、条码、分装、箱规、吊牌、洗标等。

## 生成规则

1. 页面存在多个一级选项，但没有多个有效二级选项：每个一级选项生成一个 SourceSKU。
2. 页面存在多个一级选项和多个有效二级选项：按 `一级选项 × 二级选项` 生成 SourceSKU。
3. 二级规格只有一个时不拆分，仍只按一级选项生成 SourceSKU；但必须读取该单一规格行的价格和库存，不能把价格证据一起忽略。
4. 规格名称不限定格式。`2mm（65×30）`、`加厚大号`、`蓝色-加长款`等都应使用同一套规则识别，禁止增加只针对某个商品或计量单位的正则。
5. 有效规格行必须位于“规格/尺寸”区间内，并在同一最小页面容器中同时出现价格和库存。
6. 点击一级选项后读取该选项当前显示的规格价格和库存，不能用 Offer 区间价替代 SKU 价格。
7. 库存不足、无货或售罄统一保存为库存 `0`。
8. 每个 SourceSKU 保存对应选项图片；没有独立图片时可回退到当前主图。
9. 无法可靠展开子产品时标记为未解析或解析失败，不能把多个选项拼接成一个虚假的 SourceSKU，也不能用 `0` 冒充 SKU 数量。

## 通用 DOM 识别原则

- 依靠区块标题和页面位置确定颜色区、规格区与附加服务区边界。
- 规格行不依赖固定 CSS 类名、固定宽度或固定尺寸文本格式。
- 在规格区内寻找同时包含 `¥/￥价格` 与 `库存/可售数量` 的最小容器。
- 1688 页面异步渲染时轮询等待选项出现；点击选项后短暂等待价格和库存更新。
- 供应商公司名优先读取店铺公司区域；商品标题不能作为供应商名称。

## 数据结果

每个解析结果至少包含：

- `sourceVariantId`
- `variantName`
- `specValues`
- `price`
- `stock`
- `image`
- `priceSource`
- `nodeType`

整次详情解析保存扩展 `parserVersion` 和 `capturedAt`，用于判断旧数据是否需要重新采集。

## 修改后的验收清单

运行：

```bash
pnpm test:parser
pnpm build
```

并至少在 1688 页面人工验证：

- 多颜色、无规格。
- 多颜色、多规格。
- 单一规格。
- 规格名称不是尺寸格式。
- 存在包装、贴牌或加字服务。
- 某个组合无库存。
- 页面异步加载较慢。

扩展代码更新后必须提升 `browser-extension/manifest.json` 的版本号，并在浏览器扩展管理页重新加载后再重新解析；旧采集结果不会自动变化。
